## ⚙️ Core Engineering Philosophy

I believe that writing code is only 20% of the job; the other 80% is managing complexity. To keep codebases maintainable, I strictly adhere to these core fundamentals:

*   **The Single Responsibility Principle (SRP):** I design code so that every module, component, and store has exactly one reason to change. By isolating UI presentation, behavioral actions, and network orchestration into clear, distinct domains, the system becomes trivial to test, debug, and scale.
*   **DRY (Don't Repeat Yourself):** I place a high priority on eliminating redundancy. I focus on building highly composable utility libraries, shared data hooks, and design-system primitives that maximize code reuse without introducing brittle coupling.
*   **Functional Programming Paradigms:** I lean heavily into immutability, pure functions, and predictable data transformations. By keeping state transitions explicit and minimizing hidden side-effects, I ensure the application remains stable and easy to reason about as it grows.

## 🏢 Systems & Architecture Focus

While I am framework-flexible, I specialize in designing **decoupled front-end architectures** that isolate framework-specific UI code from core business logic. 

By moving asynchronous network orchestration, real-time database listeners, and external SDK drivers out of local UI states and into dedicated service abstractions, I build applications that are resilient to backend infrastructure changes.
